# DOX — frontend-next/

## Purpose

Next.js dual-map frontend (deck.gl + MapLibre GL + globe.gl) for the Sentinel OSINT dashboard. Replaces the deprecated Streamlit dashboard (`frontend/`). Consumes FastAPI REST + SSE endpoints.

## Ownership

All files in `frontend-next/`, including `lib/`, `components/`, `app/`, `__tests__/`, `e2e/`.

## Local Contracts

- **FR-13 visual contract:**
  - Hotspot marker fill encodes `conf_score`: **green > 70**, **yellow 40–70**, **grey < 40**.
  - Hotspot marker ring encodes `alert_level`: **red ring = Critical**, **orange ring = High**, **no ring = Medium**.
  - Clicking a marker shows both `conf_score` and `convergence_score` under **distinct labels** (Confidence = source reliability; Convergence = cross-domain co-occurrence).
- Grid-cell convergence heatmap is a toggleable overlay (`HeatmapLayer`).
- Globe.gl 3D view is a toggleable alternative to the flat map. `GlobeToggle.tsx` receives `hotspots` + `onSelect` props from `app/page.tsx` (never fetches); the earth texture is bundled at `public/textures/earth-night.jpg`; unmount disposes renderer/controls/GL context. FR-13 on globe = fill color for `conf_score`, altitude + radius for `alert_level` (`lib/globe-encoding.ts`); browsers without WebGL get a fallback message.
- All API calls go through `lib/api.ts` typed client — never raw `fetch` to the API base.
- Color mapping lives in `lib/colors.ts` — the single source of truth for FR-13 colors.
- i18n: all UI strings via `useT()` from `lib/i18n.tsx`; dictionaries in `lib/locales/` (vi default, key parity enforced by test). Place names, titles, SITREPs stay English. The provider memoizes `t` on `locale` (`useMemo(() => makeT(locale), [locale])`) so consumers may depend on its reference — a fresh function per render would invalidate e.g. the admin page's `load` callback and refetch the user list on every unrelated render.
- `SearchBar` (Cmd+K) calls `GET /search` via `api.search`; selection flies the map (`focus` prop on `MapView`) and opens `HotspotDetail`.
- `HotspotDetail` header uses `hotspot.name` (fallback `Hotspot #N`); sources list numbers match SITREP `[N]` via `citation_index` from `GET /hotspots/{id}/events`. When the summary text is empty, `lib/sitrep.ts:sitrepState()` decides the message: `below_threshold` (conf_score ≤ `LLM_THRESHOLD`, won't generate) vs `pending` (conf_score > threshold, awaiting LLM). `LLM_THRESHOLD` (40) mirrors `SENTINEL_LLM_THRESHOLD` and the `> threshold` gate in `pipeline/llm_verifier.py`.
- Detail panel error contract: summary/events fetch failures show `detail.error` + a retry button that re-fetches only the failed resource; every fetch result is guarded by its own per-resource generation counter (a single shared counter would invalidate earlier in-flight fetches on every load) so a stale response can never populate the panel (the panel is also remounted per hotspot via `key={hotspot_id}`); claims failures stay fail-hidden because `claims === null` also means "not evaluated".
- SSE stream handling lives in `lib/sse.ts` with exponential backoff (1s→30s, ±500ms jitter) and an `onStatus` callback (`connecting` / `live` / `reconnecting`, types in `lib/stream-status.ts`). `useHotspots` re-exports it as `{ hotspots, status, lastEventAt, settled }`, where `settled` is a one-way latch flipped by the first `/hotspots` fetch's completion — success or failure — that the page's URL-restore gate waits on; the initial fetch is guarded on `token` (like the SSE effect), so the tokenless pre-hydration pass can never 401 and trip the latch against an empty list — that would also burn a `/hotspots` rate-limit token for a request that always fails. `components/StreamStatus.tsx` renders the dot + "updated N ago" in the top-right chip and owns its own 1s ticker so the page (and MapView's deck.gl layers) do not re-render every second. The dot encodes socket state **only** — never staleness: a healthy pipeline emits nothing for `SENTINEL_POLL_INTERVAL_S` (900s) when there is no news, so a staleness-driven colour would flag working systems as broken. `attempt` is reset on received events, never in `onopen`, or an accept-then-drop server reconnects every second instead of backing off.
- Auth context in `lib/auth.tsx` wraps the app; `useAuth()` exposes `token`, `user`, `login()`, `logout()`, `isAdmin`.
- Login page at `/login`; unauthenticated users are redirected there from `/`.
- SSE lives in `lib/useHotspots.ts` (called from `app/page.tsx`), not in `MapView` — `connectHotspotStream` with the Bearer token, re-fetching hotspots on push events. It is page-level on purpose: toggling 2D/globe must not tear down the stream.
- Layout: `app/page.tsx` is a flex row — a `position:relative; flex:1; minWidth:0` map container (all overlay controls anchor to it) with `HotspotDetail` as a flex **sibling** column (340px, full height). The detail panel must never absolutely overlay the map: an overlay panel created a ~370×713px click dead zone that swallowed marker clicks and hid `FilterPanel`. First paint renders a dark loading skeleton while auth hydrates; `html, body` background is `#0d1117` so the pre-hydration and redirect gaps never flash white.
- Overlay clearance: the top-left control row and the top-right user/logout chip both cap at `SIDE_MAX = calc(50% - 235px)` (`app/page.tsx`). `SearchBar` is centred on the map container (446px wide including padding and border), and that container shrinks by `HotspotDetail`'s 340px when a hotspot opens — a fixed pixel cap cannot track that (a 480px cap cleared the search bar at full width but buried the language toggle and legend behind it once the panel was open). The container-relative cap keeps a 12px gutter at every width in both states. The user/logout chip sits **top-right** on a `#111` background; bottom-right is reserved for MapLibre attribution, which the chip was previously illegible against.
- URL state: `lib/url-state.ts` serializes `{hotspotId, filters, heat, globe, rail, sort}` to a query string (`h`, `conf`, `alert`, `win`, `heat`, `globe`, `rail`, `sort`), omitting anything at its default so shared links stay short. `app/page.tsx` hydrates once via a lazy `useState(parseState(window.location.search))` — **not** `useSearchParams()`, which opts the route out of static rendering and fails `npm run build` without a `<Suspense>` boundary — and writes back with `window.history.replaceState`, **not** `router.replace()`, which would re-run the route and discard MapView's deck.gl view state on every slider tick. Hotspot restoration is one-shot behind a `restored` state seeded from `initial.hotspotId == null`: the URL carries only an id, so it waits for `settled` — the first *authenticated* `/hotspots` fetch's completion, success or failure (the hook skips the tokenless pre-hydration pass, so a 401 can never open the gate against an empty list) — not for rows, and `restored` also gates the write-back so a copy made before that response cannot lose the `h` param (a state, not a ref, so the write-back runs only after the restore commits). Releasing on `settled` bounds the wait: a failed fetch cannot hold the write-back closed (and filters/rail/sort unshareable) for the whole session; an empty settlement just drops the stale `h`. Without the one-shot guard, closing the restored panel would immediately re-open it. `parseState` returns a fresh `Set` per call and falls back to defaults on malformed input.
- **FR-18 triage rail**: `lib/triage.ts` provides `TriageSort` (`alert`/`conf`/`convergence`/`events`/`recent`), `TRIAGE_SORTS`, `TRIAGE_SORT_LABEL` and `sortHotspots()`, which copies rather than sorting in place (`app/page.tsx` memoizes on array reference) and applies a conf→id tiebreak so the order is total — without it, rows shuffle under the cursor on every SSE refetch. `components/TriageRail.tsx` is a flex **sibling** column to the left of the map (280px open, 36px collapsed), never an overlay, for the same click-dead-zone reason as `HotspotDetail`; `SIDE_MAX` is relative to the map container, so the search-bar clearance survives the rail taking 280px. Collapsed by default; open state and sort persist through `lib/url-state.ts` (`rail`, `sort`). `role="listbox"` / `role="option"` / `aria-selected`, Enter and Space select. Rows reuse `fillColor`/`ringColor` so the rail and the map agree on FR-13 encoding.
- `lib/useHotspots.ts` wraps SSE refetches in `trailingDebounce(fn, 3000)` (`lib/debounce.ts`, returns a `DebouncedFn` with `.cancel()`) — one refetch per burst, or `/hotspots` (60 req/min) 429s during pipeline ticks; the effect cleanup calls `.cancel()` so no refetch fires after unmount/token change.
- `TrustTierEditor` (admin-only) lists sources with dropdowns to PATCH `/sources/{id}` trust_tier.
- `api.ts` provides typed `sources()` and `updateTrustTier()` methods; all api methods accept `string | null` token.
- **FR-24**: Evidence & Consistency section in `HotspotDetail` (helpers in `lib/claims.ts`, hidden when `consistency_score` null and no claims; claim citation sups reuse `jumpTo`)
- SITREP citation parsing in `lib/citations.ts` renders `[N]` markers as superscript links.
- **FR-18**: `lib/filters.ts` provides `HotspotFilters`, `DEFAULT_FILTERS` (minConf=40), `passesFilter()`, `applyFilters()` — client-side filtering. `components/FilterPanel.tsx` renders a trigger button (title + "showing X of Y" counter + "N new" chip, always visible) that opens a popover holding the confidence slider, alert-level checkboxes, time-window selector (`24h` / `3d` / `7d` / `30d`, default `7d`; `TIME_WINDOW_HOURS`/`TIME_WINDOW_LABEL` in `lib/filters.ts`), "Mark seen" and reset. It lives in the top-left control row alongside `Legend`; the row is width-capped (`SIDE_MAX` in `app/page.tsx`, see the Layout entry above) so the trigger wraps below the centered SearchBar instead of under it; the popover opens directly under its trigger (`top: calc(100% + 6px); left: 0`), which stays clear of the search bar because the trigger itself does. `aria-expanded` on the trigger, `role="dialog"` on the body, `Escape` closes — matching the `Legend` pattern. The server caps `/hotspots` at 30 days (`max_age_hours`), so the widest client window matches the server ceiling. `components/Legend.tsx` renders FR-13 color swatches inside a hover/focus tooltip behind a `?` affordance (i18n section labels `legend.fill`/`legend.ring`, `legend.title` on the button); `aria-expanded` + `role="tooltip"` for a11y.
- **FR-19**: `lib/clustering.ts` wraps supercluster (radius=60, maxZoom=12) behind `createClusterIndex()`/`getClusterData()`/`getExpansionZoom()` (supercluster type never leaks past this module — `HotspotClusterIndex`). `lib/useCluster.ts` hook returns `{clusters, leaves, getExpansionZoom}` for the current zoom and rebuilds the index only when the `hotspots` reference changes, so callers must pass a memoized array (`app/page.tsx` memoizes `applyFilters`). `MapView` renders cluster circles + `TextLayer` counts at zoom < 7, individual markers via `ScatterplotLayer` at all zooms, and clicking a cluster flies to its `getExpansionZoom()` level. Default basemap is Carto dark-matter via the `NEXT_PUBLIC_MAP_STYLE` override; fly-to zoom `FOCUS_ZOOM=6`, cluster expansion capped at `MAX_CLUSTER_ZOOM=10` (`docker-compose.yml` passes the same Carto URL as a build arg, so containerized builds match the dev default).
- Phase-3 map triage: cluster circles ring by worst contained `alert_level` (`ClusterFeature.worst_alert`, aggregated through supercluster's `map`/`reduce`), reusing `ringColor()` — a Medium-only cluster keeps the neutral blue outline because FR-13 gives Medium no ring. Hotspot marker radius encodes `convergence_score` via `lib/marker-size.ts` (`sqrt` so area, not radius, tracks the score); this intentionally differs from the globe, where `lib/globe-encoding.ts` spends radius+altitude on `alert_level` because globe.gl points have no stroke. The convergence heatmap carries a tooltip through an invisible pickable `ScatterplotLayer` (`CELL_PICK_LAYER_ID` in `lib/map-tooltip.ts`) because `HeatmapLayer` aggregates into a texture and cannot report the cell under the cursor.
- **FR-20**: `lib/whatsnew.ts` provides `isNew()`, `countNew()`, `markSeen()`, `getLastSeen()` (localStorage key `sentinel_hotspots_last_seen`). `MapView` accepts `newHotspots` prop to render translucent highlight layer. `FilterPanel` accepts `newCount` prop to display "N new" chip + "Mark seen" button.
- **FR-24**: `lib/claims.ts` provides `orderClaims` (disputed first), `statusColor`, `statusLabelKey`, and `splitEvidence` (cited supporting vs contradicting). `HotspotDetail`'s "Evidence & Consistency" section names the disagreement per claim — "supported by [i] · contradicted by [j]" — with contradicting citations in red; hidden when `consistency_score` is null and there are no claims. `lib/clustering.ts` carries `consistency_score` through supercluster props so clustered markers keep it (hardcoding null hid the score at low zoom).
- Detail panel surfaces the data the payload already carries: per-event badges via `lib/severity.ts` (`source_system`/`event_type_label` only when the hotspot's events differ in them, `fatalities` when > 0, `num_sources` only when > 1, plus `goldstein_scale` intensity and `avg_tone`), a header aggregate (max fatalities labelled as a max, mean tone, and a `start_window`→`end_window` lifespan that collapses to a single date when both fall on the same day), NLI `probability` inline beside **contradicting** citations only (the title tooltip keeps it on all), and a 14-day activity sparkline (`lib/sparkline.ts` + `components/Sparkline.tsx`, inline SVG, no new dependency) shown only when events span more than one day. Severity styling must not reuse the FR-13 alert palette — `lib/colors.ts` stays the only source of alert/confidence colour. A leading "N reports" badge appears when `duplicate_count > 1` — GDELT emits one row per extracted actor pair, so the collapse is shown rather than applied silently. The search dropdown carries the same signal as `report_count` in the sublabel.
- Raw-events layer: `lib/events-layer.ts` (pure — `bboxFromBounds` accepts both deck.gl `getBounds()` shapes and rejects inverted envelopes, the signature of a dateline wrap; `quantizeBbox` snaps outward to whole degrees; `windowRange` reuses `TIME_WINDOW_HOURS`) + `lib/useRawEvents.ts` (debounced 800ms, refetches only when the quantized bbox key or time window changes; returns `{features, failed}` — a failed fetch clears the key cache so a same-key re-run retries, and `failed` drives an error chip in `MapView`) + `api.events()`. The fetch lives inside `MapView`, not `app/page.tsx`: unlike the SSE stream — which is page-level so switching 2D/globe does not tear it down — the raw layer is map-only and *should* unmount with the map. Renders below the hotspot markers so markers keep winning picks. **`/events`, `/hotspots`, `/search` and `/grid_cells` share one 60 req/min token bucket per client IP** (`api/ratelimit.py:52`), so an un-throttled pan handler 429s the entire app; the debounce plus bbox quantization is load-bearing, not tidiness. Only the first page is fetched, and the server orders it oldest-first (`event_id ASC`) — the request pins `pageSize: RAW_PAGE_SIZE` so the client and server agree on the boundary, and the truncation chip reads a `{n}` placeholder filled from that same constant, so the two cannot drift. `next_cursor` is deliberately not followed. An inverted envelope (viewport spans the antimeridian) sets the bbox to null and `useRawEvents` derives an empty layer, so the previous side's events do not keep rendering over the new side. The raw-events toggle is disabled in globe view, where `MapView` is unmounted. `showEvents` is intentionally absent from `lib/url-state.ts` so a shared link does not auto-fire the fetch for the recipient.
- Containerized via `Dockerfile` + `.dockerignore` for Docker Compose deployment.
- Chrome styling reads `lib/theme.ts` (`COLOR`, `SPACE`, `RADIUS`, `FONT`, plus the `panelSurface`/`chipStyle`/`buttonStyle`/`inputStyle` presets). **FR-13 encoding colour is not duplicated there** — marker fill/ring stay in `lib/colors.ts`, and `__tests__/theme.test.ts` fails the build if a `theme.ts` value ever matches one of them. `inputStyle` normalizes the box model (`box-sizing: border-box`, since `<input>` defaults to content-box and `<select>` to border-box) but pins **no height** — the admin form aligns its sibling controls to a shared bottom edge with flex stretch (`alignItems: stretch` + `flex: 1` on each control inside equal-height labels), because `<input>` and `<select>` have different intrinsic heights that no single fixed pixel can match. `app/globals.css` applies `var(--font-geist-sans)` (nothing consumed the variable before, so every screen rendered in the browser default) and re-declares it on form controls, which do not inherit `font-family`. `<html lang>` is `DEFAULT_LOCALE` for first paint and `LocaleProvider` syncs `document.documentElement.lang` on every toggle.
- `components/Section.tsx` is the collapsible block used throughout `HotspotDetail` (`aria-expanded`, count stays visible while collapsed). Sections accept optional `open`/`onOpenChange` for controlled mode. **The Sources section's open state is lifted into `HotspotDetail`** (open by default): `jumpTo` resolves `[N]` citations through `listRef.current?.querySelector`, and a collapsed section unmounts the `<ol>`, so the FR-16 citation jump would silently no-op — `jumpTo` forces the section open before scrolling. The score section renders one `<dl>` with `<dd>` definitions (a `<div>` sibling of a `<dt>` is invalid `<dl>` markup and breaks the term/definition pairing).
- **M9 score literacy (FR-27):** `components/ScoreHelp.tsx` is the per-score `?` affordance (`aria-expanded` on the button, `role="tooltip"` panel, Escape closes) opening a definition / how-to-read / common-misreading help for each score name. The detail panel no longer prints raw DB column identifiers (`conf_score:` etc.) — the human labels already in `lib/locales/` stand alone.
- **M9 window comparison (FR-28/FR-29):** `lib/window-metrics.ts`, `lib/window-consistency.ts`, `lib/compare.ts`, `lib/export.ts`, `components/CompareDialog.tsx`. Load-bearing facts — **every windowed figure is labelled recomputed, not published**: the server's weights/thresholds are env vars the client cannot read, so each module recomputes over the full range and checks against the published score (`confTrusted`, `consistencyTrusted`), degrading to raw/counts-only on mismatch rather than guessing. Windowed convergence is `typesOnly` (inputs only) because the published `convergence_score` is grid-cell derived, not hotspot-local. Claims with NULL `origin_domains` (pre-migration-023) are `unverifiable` and force `countsOnly` — never assumed to have an empty origin set; a claim whose evidence all falls outside a window is likewise `unverifiable` (judging it would manufacture a score of 50). Empty-window `sourceDensity`/`diversity`/`conf` are **null, not 0** — 0 would render as a fabricated "Confidence 0.0 ↑ 70.0" drop. The narrative report (`api.report`) is **never fetched on mount** — the endpoint is capped at 4/min and costs an LLM call. `CompareDialog` opens from a Compare button in the score section, defaults to last-24h vs preceding-24h with equal-length durations (`TIME_WINDOW_HOURS`), exports CSV/JSON/Markdown via client-side Blob download (the anchor is appended to `document.body` and the object URL revoked after a delay, or Firefox silently drops the download), and is portaled to `document.body` so the print stylesheet (`body > *:not(.print-root)`) can isolate it. It takes focus on open (so Escape/Tab land on the dialog — a keydown handler on an unfocused div is dead in real use), traps Tab within the panel, and clears a generated report when the duration changes so a stale narrative never ships under new window headers. Direction colour is per-metric polarity via `compare.deltaTone` (more confidence/consistency good, more fatalities bad, counts neutral) — never the FR-13 alert palette from `lib/colors.ts`.
- Score transparency: `lib/score-breakdown.ts` splits `conf_score` into `0.7 × source_density` + `0.3 × geopolitical_diversity` and `convergence_score` into `types × 25` + `min(25, events × 2)`, rendered by `components/StackedBar.tsx` (inline SVG, no charting dependency). The conf weights are **env-overridable server-side**, so `confBreakdown` reconstructs the published score and falls back to `mode: "raw"` when the reconstruction misses by more than 0.51. The convergence formula is **hardcoded** (`pipeline/clustering.py`, no env override), so a convergence reconstruction miss can only mean inconsistent inputs — its raw branch shows a `breakdown.rawConvergence` caveat and nothing else (bare inputs under the printed score would read as an explanation). `convergence_score` is **nullable** in `schemas.Hotspot`/`lib/api.ts`: NULL means the hotspot never went through grid-cell convergence, so `convergenceBreakdown` returns `unavailable` ("not yet scored") when it is null, when `types`/`events` are absent, or when `types === 0 && events === 0` — a hollow track under "convergence 0.0" is inert chrome. Consumers must not NaN: `radiusForConvergence` floors null to `MIN_RADIUS`, the triage convergence sort treats null as 0 (`?? 0`, bottom of a descending sort), and the detail panel renders a `—` instead of `toFixed` on null. `StackedBar`'s `aria-label` and visible legend both report the **raw** segment values (so the sighted and non-visual readings agree) and, when `max/sum < 1`, append a `clampNote` (the caller passes `breakdown.clamped`) explaining that the track is narrower than the numbers add up to. `sourceMix` counts **unique domains, not events**, because `pipeline/scoring.py` sums trust and reads `country_code` over unique domains; counting events would let one prolific outlet dominate a chart that claims to explain `source_density`. The consistency bar reuses `statusColor` from `lib/claims.ts` so it agrees with the claim list beneath it.
- Login (`app/login/page.tsx`): fully i18n'd, theme-token styled, labelled inputs, `role="alert"` errors, and submit disabled in flight. `lib/auth.tsx` throws a typed `LoginError` with `kind: "credentials" | "network"` — `fetch` only rejects on transport failure, and reporting an unreachable API as "wrong password" sent people hunting for a typo while the container was down. A 429 from the auth limiter maps to `network` on purpose: a distinct "too many attempts" string would tell an attacker where the throttle sits.
- **No public signup** (product decision, 2026-08-04). Accounts are created by an admin at `/admin/users`, so the `users` CHECK constraint (`analyst`/`admin`) needs no migration and no unauthenticated endpoint grants intel access. The page guards on `isAdmin` for convenience only; `require_role("admin")` on the server is the control. The last-admin rule is deliberately **not** mirrored client-side — the client would need a duplicated admin count, and a stale one would either hide a legal button or offer an illegal one. The page returns `null` before auth hydrates (an SSR'd "admin access required" first paint flashes the forbidden screen to a logged-in admin) and redirects logged-out visitors to `/login` like the dashboard. Both `create` and `remove` share one `busy` guard — a double click on Delete would 404 the second call after the first succeeded. API errors are typed: `lib/api.ts` throws `ApiError` (with `status`), so the page branches on `err instanceof ApiError && err.status === 409` for the duplicate-username message instead of string-sniffing the formatted path. The user table has a header row (`login.username` / `admin.users.role` / `admin.users.created`), which is what `admin.users.created` labels.

## Work Guidance

- All new components go in `components/` as `"use client"` if they use browser APIs.
- Pure-logic modules go in `lib/` with corresponding tests in `__tests__/` (TDD).
- Component tests in `__tests__/` mock `@/lib/api`, `@/lib/auth`, `@/lib/i18n`, and `TrustTierEditor`; assert through the imported vi dict (`viLocale["detail.retry"]`) so copy edits in `lib/locales/` don't break assertions, and keep `@/lib/auth`'s token in a `vi.hoisted` object so a test can supersede an in-flight fetch (generation counter).
- Map-related components must be imported via `dynamic(..., { ssr: false })`.
- Do not import from `api/` (backend) — the frontend talks exclusively through the REST API.
