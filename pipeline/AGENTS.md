# DOX — pipeline/

## Purpose

Core OSINT processing: GDELT + ACLED ingestion, grid-cell convergence, DBSCAN clustering, confidence scoring, and LLM verification. Runs as a scheduled pipeline via APScheduler.

## Ownership

All files in `pipeline/` except `workers/` (see child doc).

## Local Contracts

- **Connection pool**: always call `get_pooled_connection()` from `pool.py`; always return with `pool.return_connection(conn)` in a `finally` block — never open raw `psycopg2` connections
- **GDELT**: `fetch_latest_existing_url` HEAD-checks the newest export candidates from the master file list, because a file can be indexed minutes before it is served. That HEAD **must** pass `allow_redirects=True`: `requests.head` does not follow redirects by default (unlike `get`), and `data.gdeltproject.org` answers plain http with a 301 to https, so every candidate scores 301, nothing is ever "accessible", and the tick dies with `None of the top 5 export files are accessible`. That is not a transient network error — it killed ingestion for six days (no events 2026-08-21..26, found 2026-08-27), and because the worker logs it as a normal tick failure nothing else raised an alarm. Guarded by `test_latest_existing_url_follows_redirects`, which asserts the flag reaches `requests.head` rather than mocking around it.
- **ACLED**: authenticates by any one of `ACLED_ACCESS_TOKEN` (a token pasted from myACLED, used until its JWT `exp`), `ACLED_REFRESH_TOKEN` (refresh grant, tried before the password grant and rotated on every use — ACLED returns a new refresh token each time) or `ACLED_EMAIL`/`ACLED_PASSWORD` (password grant). `acled_credentials_configured()` is the single gate all three call sites use (`pipeline.py` Step 2, `workers/ingestion_worker.py`, `main_acled`) — do not re-test the env vars inline, a token-only setup then looks unconfigured. Re-auth with only a static token raises rather than posting empty credentials. Bearer token cached 24h in Redis/in-memory; rate-limit to 1 req/s; cache responses in Redis with TTL = `SENTINEL_ACLED_POLL_HOURS × 3600`; fall back to GDELT-only on failure. **401 and 403 mean different things**: 401 is a bad/expired token and triggers re-auth, 403 `Access denied` means the token authenticated but the account has no API data access — `_fetch_page_with_retry` returns immediately on 403, because retrying an entitlement failure only burns the tick. ACLED assigns generic email domains (gmail etc.) the **Open** access level, which excludes the API entirely: every endpoint answers 403, including the reference tables `country/read` and `region/read`, while a garbage token still gets 401. API access requires registering with an academic domain — the project account is `0223b0239@ms.hanu.edu.vn` (verified working 2026-08-21). **That tier serves data on a rolling 12-month embargo**, which ACLED states in every read envelope as `data_query_restrictions.date_recency` (`{quantity: 12, unit: Months, date: <cutoff>}`; cutoff was 2025-08-22 on 2026-08-22, and it rolls daily). `_note_query_restrictions` stores that dict on the ingestor and warns when the requested window starts after the cutoff — otherwise an embargoed fetch authenticates, returns 200, and yields an empty frame with nothing in the log to explain it. No country, region or event-type restrictions apply to this account (2,737,020 rows reachable). `fetch_events(days=7)` therefore contributes nothing to the live tick — ACLED data is usable for historical/backtest work, not for same-day convergence, and any claim that a hotspot is ACLED-corroborated must be checked against this
- **M6 evidence & claim quality**: `fetch_hotspot_evidence` returns **one representative (most recent) row per unique domain** — `citation_index` stays the row's position in the FULL FR-16 article list so `[N]` markers still resolve. Deduping is required: a 34-row prompt exceeded NIM's latency budget (6/7 calls 500'd or timed out). `extract_claims` drops degenerate claims via `is_valid_claim` (min `SENTINEL_CONSISTENCY_MIN_CLAIM_WORDS` words + one lowercase word); GDELT titles are bare actor names, so without this the engine scores fragments like `WASHINGTON` as all-disputed (observed `consistency_score` 0.0 on live hotspot 24783). No surviving claims ⇒ engine returns None ⇒ score stays NULL (honest "not evaluated").
- **M8 relevance gate** (`pipeline/relevance.py`, FR-26): `judge_claims` accepts a `sim` matrix and only sends pairs at or above `SENTINEL_RELEVANCE_MIN_SIM` to the NLI model — MNLI assumes premise and hypothesis share a scene, so ungated off-topic pairs return "contradiction" by construction (measured on clean data: 32 of 63 live claims disputed, 0 corroborated). Gated pairs are still emitted as `neutral`/0.0, so `claim_evidence` and the FR-16 citation contract are unchanged; `sim=None` disables gating for callers that want the old path. `filter_vacuous_claims` drops flat-similarity claims **only when `evidence_homogeneity < SENTINEL_RELEVANCE_MAX_HOMOGENEITY`** — without that guard a correct specific claim in a single-topic hotspot is also flat and would be dropped, discarding the corroboration case the engine exists to reward. `dedupe_claims` collapses repeated claims (24795 scored three identical "Russia is mentioned" rows separately, reaching 87.4). Unlike NLI, the embedder is **fail-closed**: `RelevanceUnavailable` propagates to `run_consistency_engine`'s existing handler so the engine skips and `consistency_score` stays NULL — never add a narrower try/except that defeats this. `SENTINEL_MIN_GEO_PRECISION` stays at 2 (M8 non-goal).
- **M7 GKG headlines** (`pipeline/gkg.py`, FR-25): `run_once()` fetches the GKG file paired with the export file and stores `{url: headline}` on `GDELT2Ingestor.latest_headlines` (a declared dataclass field — the class is `slots=True`, so undeclared attributes raise). `_augment_records` writes `headlines.get(url) or Actor1Name` into `title`; `actor1_name` keeps the raw actor. Every GKG failure path returns `{}` and degrades to pre-M7 titles — enrichment must never block a tick. `pipeline.py` and `workers/ingestion_worker.py` need no changes because `insert_to_db*` default `headlines=None` to the instance map. Backfill: `python -m pipeline.gkg --backfill --days N`; un-enriched rows are `title IS NULL OR title !~ '[a-z]'` (ALL-CAPS actor names vs lowercase headlines) — do **not** use `title = actor1_name`, it misses every row ingested before FR-21. A 7-day walk is ~670 files at ~5 MB, so the backfill exits as soon as the pending set empties and honours `--max-files`.
- **LLM transport**: `call_llm_raw` retries **429 and 5xx** before the Ollama fallback, but on **separate schedules** — NIM 500s are transient and the fallback may not exist on the host. 5xx keeps `2**attempt` (2s, 4s). A 429 is a quota clock, not a transient fault: `2**attempt` retries inside the same rate-limit window, so all three attempts land in the bucket that just rejected them and the hotspot drops to the fallback for nothing (measured: 4 exhaustions in a 5-minute window once the NIM queue ran at full speed, each cascading into an Ollama `Uncited sentences` rejection). 429 therefore uses `Retry-After` when NIM states it, else `SENTINEL_LLM_RATELIMIT_BACKOFF_S` (default 15) doubling per attempt; a wait above `SENTINEL_LLM_RATELIMIT_MAX_WAIT_S` (default 60) falls back immediately rather than parking the single-threaded worker and stalling every hotspot queued behind it. `_retry_after_seconds` deliberately does not parse the HTTP-date form — it returns None and the schedule covers it. A 429 that **clears** logs `<provider> 429 cleared after N retries (Ms waited)` at INFO (from `pipeline/llm_providers.py`, provider-agnostic): without it only the exhausted 429s are visible and the backoff cannot be distinguished from a no-op in production. That log requires `workers/llm_worker.py:configure_logging` — with no handler configured the root logger falls back to `lastResort`, which drops everything below WARNING, so every INFO in this path was silently discarded. It sets the root level explicitly after `basicConfig` (which is a **no-op once the root logger has a handler**, the same silent-failure shape) and pins `httpx`/`httpcore` to WARNING: raising the root level otherwise switches on one httpx line per HuggingFace request, burying the signal the level was raised for. When `NVIDIA_NIM_ENDPOINT` is empty the chain resolves without NIM (and `nim` is out of the default chain anyway), and `endpoint_of` falls back to each provider's default — an Ollama-only host reaches `call_ollama_raw` without ever POSTing to `""`. Fallback model is `SENTINEL_OLLAMA_MODEL` (default `llama3:8b`); on 8 GB hosts pull `llama3.2:3b` and run `OLLAMA_HOST=0.0.0.0 ollama serve` so containers can reach it via `host.docker.internal`.
- **M11 provider chain (FR-31)** (`pipeline/llm_providers.py`): all LLM transport lives here. NIM, DeepSeek and Kimi share one OpenAI-compatible adapter (`/chat/completions`); Ollama (`/api/generate`) keeps `call_ollama_raw`, moved **verbatim** with its FR-12 audit tag (`llama-3-8b-ollama`, or `<model>-ollama`), while OpenAI-compatible providers report `provider:model` (e.g. `deepseek:deepseek-v4-flash`) in `llm_summaries.llm_model_version` — both forms satisfy the worker's `"ollama" in model_used.lower()` fallback check. `SENTINEL_LLM_PROVIDERS` (default `deepseek,kimi,ollama`) names the ordered chain; an unknown name or a provider whose `key_env` is unset is dropped **when the chain is built**, before any request (same treatment `translate_enabled()` gives an unconfigured optional integration), and a chain that resolves to nothing raises `NoProviderConfigured` — "nothing was configured" and "everything failed" are different failures and only the first is worth an alert. Per provider, in order: 2xx returns `(content, tag)`; Timeout and connection errors log and fall through; 429 retries `Retry-After` else exponential backoff, capped by `SENTINEL_LLM_RATELIMIT_MAX_WAIT_S` (the cap survives because the worker is single-threaded — parking it stalls every queued hotspot), then falls through; 5xx retries `retries` times then falls through; **401/402/403 fall through immediately with no retry** (a rejected key or exhausted quota does not clear within a tick — the same conclusion `_fetch_page_with_retry` reached for ACLED's 403 — logged at WARNING with the provider name); **400 raises and never falls through**: a malformed request is our bug and every provider rejects it identically, and falling through would end at Ollama answering a prompt the paid providers refused while the run looks successful. `nim` is implemented but **out of the default chain** (it was timing out on every call when the chain landed); any deployment that wants it adds it to `SENTINEL_LLM_PROVIDERS`. Paid providers are gated on `conf_score > SENTINEL_LLM_PAID_MIN_CONF` (default 70) — a **second, higher threshold** than `SENTINEL_LLM_THRESHOLD`, which still decides whether a SITREP happens at all. The tier is resolved **once per hotspot in `generate_sitrep`** (`LLMRepository.fetch_conf_score`) and passed as `partial(call_llm, conf_score=...)` into the engine and the SITREP, so claim extraction and SITREP can never split tiers and `llm_model_version` stays honest; `_default_llm` (the unbound CLI default) resolves with `paid_allowed=False` so a manual `python -m pipeline.consistency` run cannot silently spend. `call_llm_raw`/`call_nim_api` in `llm_verifier.py` are a back-compat shim that applies their NIM/ollama arguments as env overrides before delegating to `call_llm`. The deepseek adapter sends `thinking: {type: disabled}`: `deepseek-v4-flash` reasons by default and on real prompts the reasoning eats the whole `max_tokens` budget, so the API answers 200 with empty `content` (measured 8-16k reasoning tokens, finish=length at 2000-4000 max_tokens) — with thinking off the extraction prompt returns ~1k content tokens in ~3s. The flag is deepseek-only; NIM/Kimi must not receive a param they may reject. Metrics: `llm_calls_<provider>_total` (per attempt, not per success), `llm_failures_<provider>_total`, `llm_paid_skipped_total`; `llm_fallback_total` keeps its meaning.
- **`consistency_score` formula (FR-22(d))**: `100 × Σ w·v / Σ w` where `w = max(support + dispute, 0.1)` and `v = _STATUS_VALUE[status] × support/(support + dispute)`, falling back to `_STATUS_VALUE[status]` when `support + dispute == 0`. **Weight and value are different quantities and must stay separate**: weight is how much evidence bears on the claim, value is how much of it agrees. Folding dispute into the weight alone (the pre-2026-08-20 form) meant a dispute vote *raised* a claim's weight without lowering its value, so a contested claim contributed MORE than a clean claim of equal support whenever the contradiction failed to flip the status — `dispute >= ratio × support` lets that through at high support. The 0/0 branch is the modal case, not an edge case (448 of 597 claims on the 2026-08-20 snapshot have every pair gated by FR-26 or below `SENTINEL_NLI_MIN_PROB`); reading it as 0 would accuse three quarters of all claims of being contradicted. `_DISPUTE_PENALTY_K` is hard-coded at 1 and **must never become an env var** — `k >= 1` is required for the numerator `V×(support + (1−k)×dispute)` to stop rising with dispute and `k <= 1` for the penalty factor to stay non-negative, so 1 is the only admissible value and a knob could only be turned wrong. Rejected alternatives, measured offline on the same snapshot (`eval/consistency/weight_backtest.py`): `w = max(support, 0.1)` and `w = max(support − dispute, 0.1)` both **mute** disagreement rather than penalising it — a hotspot whose claims nine domains contradict rose from 65.9 to 95.8/97.4 — and a bare `support/(support+dispute)` value discards the FR-22(c) two-domain corroboration gate, scoring a single-source claim 100. **This formula is duplicated in `frontend-next/lib/window-consistency.ts:claimValue` (FR-28) and the two copies must change together**; a one-sided edit raises nothing, it just makes `consistencyTrusted()` always false. `tests/fixtures/claim_value_parity.json` binds them (generator: `tests/test_consistency_parity.py`).
- **M6 Consistency Engine** (`pipeline/consistency.py` + `pipeline/nli.py`): shared entry point `generate_sitrep` (6a+6b, used by monolith Step 6 and LLMWorker); engine never blocks the pipeline (`consistency_score` NULL on failure, headline-prompt fallback); `fetch_hotspot_evidence` is in FR-16 citation lockstep with `fetch_hotspot_articles` — the three queries (articles, api events, evidence) must change together; `validate_citations` accepts the FR-23 two-index dispute pattern; NLI is lazy/optional via `pipeline/nli.py` (`NLIUnavailable`)
- **M9 (FR-28)**: `ClaimVerdict` carries `origin_domains: list[str]` (the domains that asserted the claim, resolved from `source_indices` at consensus time) and `ConsistencyRepository.save` persists it to `claims.origin_domains` (migration 023). It is stored as **domains, never `source_indices`**: citation indices are re-derived on every fetch by `assign_citation_indices`, so persisted indices would drift onto different events. NULL on read means "written before 023", which a consumer must treat as unverifiable, not as an empty set
- **M9 (FR-29)** `pipeline/window_report.py`: `build_window_report_prompt` builds the window-scoped narrative prompt from ONLY the window's events and states the bounds, so the model cannot narrate outside the range asked about; `window_citations` renumbers citations `[1..N]` within the window via `collapse_duplicate_urls` (a filtered slice of `fetch_hotspot_events` would otherwise inherit gaps like `[4]`, `[7]` and cite rows the report does not contain); `report_timeout` reads `SENTINEL_REPORT_TIMEOUT_S` (default 30). The report must satisfy `validate_citations()` like every SITREP
- **M10 (FR-30)** `pipeline/translate.py` — citation-safe helpers for the Vietnamese display translation (Google Cloud Translation v2, never an LLM). `protect_citations` wraps every `[N]` marker in `<span translate="no">` and `restore_citations` unwraps, unescapes, and closes the space Google opens between a marker and the punctuation after it (the wrapper reads as a word, so `Dabholkar [1].` comes back as `Dabholkar [1] .` — observed live on hotspot 12554) after the call: Google honours that tag ONLY with `format: "html"` — in `text` mode there is no way to exclude a segment, and a translated `[N]` breaks FR-11 validation and the detail panel's click-to-jump. `translate_batch` POSTs once with a multi-`q` body (v2 returns translations in input order — verified live) and RAISES `TranslationUnavailable` rather than returning partial output, because a short or reordered response would misalign claims against their `claim_id`s. `translate_enabled()` gates on `SENTINEL_TRANSLATE_ENABLED` AND a `GOOGLE_TRANSLATE_API_KEY`; the key is server-side only and no scoring path reads a translated string — English stays canonical.
- `pipeline/citations.py` owns `collapse_duplicate_urls()` — the single definition of "one article = one citation" (FR-16). All three citation-list producers (`api.queries.fetch_hotspot_events`, `LLMRepository.fetch_hotspot_articles`, `consistency.fetch_hotspot_evidence`) must apply it to the same ordering. Collapsing in one and not the others shifts every `[N]` above the first duplicate and repoints SITREP markers at the wrong article.
- **FR-WM-CONVERGENCE**: a 1°×1° cell is an active zone when `convergence_score ≥ 1` (≥1 classified event in 24 h) — not DBSCAN density. 2+ distinct types raise the alert level but aren't required to activate, so GDELT-only feeds still produce hotspots. `classify_event_type` reads the **2-digit CAMEO root** of GDELT's 3–4 digit `EventCode` (`_cameo_root`); roots 14–19 → `military_conflict`. `_load_cell_events` floors the DBSCAN window lower bound to start-of-UTC-day (`_dbscan_window_start`) so day-granular GDELT events stay in window all day. `save_clusters` diffs against existing cell hotspots by non-noise event membership — unchanged clusters keep their `hotspot_id` (and `llm_summaries` row); only stale hotspots are deleted. `_load_cell_events` also drops rows with `geo_precision < SENTINEL_MIN_GEO_PRECISION` (default 2; NULL fails open) so GDELT country-centroid mention piles never enter DBSCAN; `load_events_for_convergence` deliberately keeps them (FR-WM bins all events).
- **conf_score**: `0.7 × source_density + 0.3 × geopolitical_diversity`; `source_density = tanh(sum(trust_weights)/3)` (env-configurable via `SENTINEL_CONF_W_DENSITY`, `SENTINEL_CONF_W_DIVERSITY`, `SENTINEL_CONF_DENSITY_DIVISOR`) — must match specs.md FR-7/FR-8/FR-9 exactly. Diversity reads `sources.country_code` over unique domains.
- **source_country.py**: `resolve_country(url_or_domain)` maps domains to ISO-A3 via curated outlets + ccTLD fallback; `backfill_source_countries(conn)` one-time backfill with `python -m pipeline.source_country --backfill` CLI.
- **LLM**: validate every sentence ends with `[N]` via `validate_citations()` (regex `\[\d+\]` accepts a **single** index only — `build_prompt` must instruct the model to emit one index per sentence and never `[1, 2]`, or rich multi-source hotspots get permanently rejected). The sentence splitter must not treat single-capital abbreviations (`U.S.`, `E.U.`) as boundaries — the `(?<![A-Z]\.)` lookbehind guards this; without it any summary mentioning "the U.S. Senate" is rejected. Fall back to Ollama when NIM is unavailable. Parse model output with `_extract_json()` (tolerates ```` ```json ```` fences/prose — never bare `json.loads`). `LLMSummary._coerce_text` collapses a list-valued `summary`/`conflict_detail` into a string before validation — the model intermittently returns sentence lists, and `sources_cited` had a coercion while these did not, so a formatting quirk discarded the whole hotspot. Coercion runs `mode="before"`, so FR-11 still applies to the joined text; it is not a way to smuggle uncited sentences through. On an FR-11 rejection `call_nim_api` re-prompts **exactly once** via `build_repair_prompt` (original task + the validator's complaint + the rejected answer, "correct only the citations"), gated by `SENTINEL_LLM_CITATION_REPAIR` (default true). The rejected call is already paid for, so one repair costs far less than losing the hotspot; a second failure propagates rather than looping, because a model that cannot cite must not be retried forever. NIM request params are env-configurable: `SENTINEL_LLM_TIMEOUT_S` (default 60 — must exceed 70B generation time or every call times out), `SENTINEL_LLM_MAX_TOKENS` (default 500), `SENTINEL_LLM_TEMPERATURE` (default 0 — but at 0 a summary that fails `validate_citations` fails identically on every retry, permanently rejecting that hotspot; observed with `mistralai/mistral-nemotron` emitting `[1, 2, …]` on ~13% of hotspots. A small temperature, e.g. 0.3, lets retries vary and eventually pass). Note: `sentinel.env` points `OLLAMA_ENDPOINT` at `host.docker.internal:11434` (localhost inside a container is the container itself); the fallback still requires Ollama running on the host. A failed NIM+Ollama call is acked by the LLM worker (`llm_failed_total` metric) and retried on the next tick's re-emission — never left pending for the stale-claim sweep. LLM generation is skipped when `llm_summaries` already has a row for the hotspot (`candidate_hotspots` NOT EXISTS filter + `LLMWorker.summary_exists` guard); with stable hotspot identity, an existing summary means membership is unchanged.
- **Scheduler**: full cycle period controlled by `SENTINEL_POLL_INTERVAL_S` (default 900 s)
- **Hotspot TTL**: `retention.delete_stale_hotspots(conn)` deletes hotspots whose `end_window` is older than `SENTINEL_HOTSPOT_TTL_HOURS` (default 720 = 30 days); `event_hotspot` links cascade. Called every `IngestionWorker.tick()` (worker deployment) and in `pipeline.py` Step 0 (monolith). Without it, aged-out grid cells are never re-clustered so their hotspots render forever.

## Work Guidance

- Filter GDELT to CAMEO codes 14–19 (military events) only
- `scoring.py` owns `conf_score`; `clustering.py` owns `convergence_score` — keep them separate
- `convergence_score = min(100, event_types × 25 + min(25, total_events × 2))` — World Monitor formula, not Sentinel's contribution
- Do not add retry loops without backoff; ACLED's academic tier enforces rate limits
